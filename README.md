# みうらの釣りえさ屋ホームページ

GitHub Pages で公開している静的サイトです。公開ルートは `docs/` です。

## 公開構成

- `docs/index.html`
  サイト本体の HTML
- `docs/src/news.js`
  新着情報の取得と描画
- `docs/src/menus.js`
  商品一覧の取得と描画
- `docs/assets/css/site.css`
  このサイト専用の UI / UX 調整
- `docs/assets/css/style.css`
  既存テーマ由来のスタイル
- `docs/assets/js/main.js`
  このサイトで実際に使っている最小限の挙動
- `docs/assets/lib/`
  ベンダー資産。原則として直接編集しない
- `docs/CNAME`
  GitHub Pages のカスタムドメイン
- `_config.yml`
  GitHub Pages / Jekyll の設定

カテゴリを追加・削除する場合は、`docs/index.html` のカテゴリ見出しとナビゲーションも合わせます。

カテゴリ選択を常に表示し、商品名検索は「商品名で探す」を開いたときに表示します。検索欄を閉じても入力済みの条件は維持し、折りたたみ見出しに検索語を表示します。「条件をクリア」で検索・カテゴリ・在庫条件を解除し、検索欄を閉じます。

商品名検索は全角・半角、ひらがな・カタカナを区別せず、空白区切りの複数語に対応します。カテゴリと「在庫ありのみ」を併用できます。現在のデータでは各商品に1つのカテゴリが付いているため、種類とメーカーを独立した2軸として組み合わせる絞り込みには対応していません。

## 情報の日付と読み込み

- 「情報取得日時」はAPIから掲載データを取得した日時（日本時間）です。在庫を確認・更新した日時ではありません。実際の在庫確認日時の表示にはAPI側の項目追加が必要です。
- お知らせは掲載日順に並べ、90日より前のものを「過去のお知らせ」に折りたたみます。本文は削除せず、古いという理由だけで内容が無効とは判断しません。
- API取得は15秒でタイムアウトし、「もう一度読み込む」で再試行できます。保存済みデータがあれば先に表示します。
- 商品キャッシュは生データを保存するv2形式です。旧バージョンのHTMLキャッシュは再利用しません。
- 商品写真と外部の商品説明は別リンクとして表示します。いずれも新しいタブで開き、検索条件を維持します。

## SEO・店舗情報の運用

- 正規URLは `https://xn--p8je3b2frdvci4270g512e.com/`（日本語表記：`https://みうらの釣りえさ屋.com/`）。`index.html` は同じページなのでサイトマップに載せず、サイト内のトップへのリンクも `/` に統一します。
- `docs/index.html` のタイトル、description、OGP、本文で「三浦市三崎」「みうら海王系列」を案内します。系列先の公式表記は「みうら海王」です。
- 店舗・WebSite・WebPage のJSON-LDは `docs/index.html` に静的に記述します。住所・営業時間・休日を変更するときは、本文・メタ情報・JSON-LDも同時に更新してください。火曜祝日の営業や臨時休業は本文で案内し、確定した個別日程がある場合のみ構造化データの `specialOpeningHoursSpecification` に追加します。
- 系列の海上釣り堀は別の施設なので、店舗と同一の実体を意味する `sameAs` には指定しません。住所・電話番号・口コミなどの未確認情報は追加しません。
- `docs/robots.txt` から `docs/sitemap.xml` を案内します。サイトマップの `lastmod` は内容の更新日時を正確に維持できる場合にだけ追加します。
- 商品と在庫は引き続きAPIから取得します。取扱種類と店舗案内は静的HTMLでも読めますが、個々の商品が検索に載る保証はありません。

公開後の確認：

1. GitHub Pages の「Enforce HTTPS」と、HTTP→HTTPSの恒久リダイレクトを確認します。`/index.html` のサーバー側301転送はGitHub Pages単体では設定できないため、canonicalでルートURLに統合します。
2. 該当ドメインのSearch Consoleで `sitemap.xml` を再送信し、HTTPSルートをURL検査します。「ユーザーが指定した正規URL」と「Googleが選択した正規URL」を確認して、更新後のクロールを依頼します。HTTP版が「代替ページ（適切なcanonicalタグあり）」になること自体は異常とは限りません。
3. Googleのリッチリザルトテストで公開URLの店舗データを確認します。構造化データは表示や順位を保証しません。
4. 店舗のGoogleビジネスプロフィールで、正式な店舗名・住所・営業時間・祝日営業時間・サイトURLを実店舗と一致させます。プロフィールの所有者権限が必要です。店舗名に検索語を付け足さず、外観・入口・2階への経路がわかる写真を掲載します。
5. Search Consoleの検索パフォーマンスで下記の語群の表示回数・クリック・CTR・平均掲載順位を記録し、公開前後の28日間など同じ期間で比較します。天候・釣行シーズン・営業日の影響も併記します。

## ローカル確認

GitHub Pages と同じく、`docs/` をそのまま静的配信して確認します。

例:

```bash
cd docs
python3 -m http.server 4000
```

ブラウザで `http://localhost:4000` を開いて確認します。

`file:///.../index.html` を直接開くと、ブラウザのセキュリティ制約で `fetch` が失敗し、商品一覧や新着情報が正常に表示されません。

## 確認ポイント

- ページが開く
- ナビゲーションのアンカーリンクが動く
- スマホ表示でメニュー開閉が動く
- 新着情報が表示される
- 商品一覧が各カテゴリに表示される
- 外部リンクが正しく開く
- 画像のパス切れがない

## 運用メモ

- GitHub Pages の公開対象は `docs/` を前提にする
- `docs/assets/lib/` は古いテーマ由来の資産を含むため、削除や差し替えは実際の画面確認を前提に行う
- 見た目の調整は、まず `site.css` に寄せて進める
